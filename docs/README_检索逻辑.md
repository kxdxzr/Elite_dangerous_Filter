# GUI 检索逻辑

下述源码新增功能已包含在 [v0.1.4-beta.2](releases/v0.1.4-beta.2.md)；
旧“仅当前源码／未包含在beta.1”说明用于区分之前的EXE。

最少任务派系数为0时，“无 RES 命中时回退 CNB”仍可选择。先合并并复核任务及补充 RES 候选，仅当合并后的筛选结果没有 RES／未知命中且两部分查询均完整时返回 CNB。新增 RES 命中会阻止任务目录单独触发 CNB 回退；明确无环不排除 CNB，CNB 不要求有环。

当前源码：有已知任务来源的结果按来源星系去重，补查 Spansh 控制小派系（最多4个在途请求），多个来源分别标注。无来源的来源控制派系显示 **`-`**，不借用目标星系控制派系。补查失败保留候选、显示 **情况未知**并记录诊断。界面及 CSV 其他空字段统一显示 **`-`**，明确的情况未知／无数据不替换。

启动：`python filter_gui.py`。

检索流程为：复制并校验条件 → 检测矛盾 → 解析参考星系 → 固定服务器查询 → 分页去重 → 本地逐行 AND 复核。

- 单行“属于其一”是 OR，不同行之间都是 AND。
- 经济、类型等标量的重复条件取交集；服务、舰船、商品等集合条件分别验证。例如“有市场”和“有船厂”允许同时成立。
- 可下推的条件转换成 Spansh 官方格式。多个集合条件先下推并集候选，再本地检查每一行；包含、不属于、双边范围外等条件需要本地复核。
- 多参考点距离优先下推最小的有限范围，其余参考点按坐标精确复核。单边范围外转换为服务端范围，严格边界仍由本地检查。
- 多个有限范围内条件会进一步计算交集包围体：星系查询下推交集的 x/y/z 包围盒，并在更紧时从两参考点的中点查询。每个结果仍检查全部原始距离条件；多点查询因此优先返回交集中心附近的命中。
- 搜索每页默认取 500 个候选，减少网络往返；“最多翻页”仍表示请求页数。引擎调用可使用 `page_size`（1~500）覆盖默认值。
- 搜索不会修改传入条件；名称纠正通过 `corrections` 返回。状态栏下方有进度条：解析参考星系和等待单页响应时转圈，每页完成后按“已复核候选 / 预期候选”显示百分比和命中数，结束时显示完成 / 已停止 / 未完成。
- 后端未返回的字段：若条件已精确下推，则使用后端判断；需要本地复核却缺数据时，不计为命中并明确提示“无法确认”。
- 船名（48 个）/模块名（153 个）本地全量内置，秒回且离线可用；后台增量补充只增不减。输入打字联想，失焦即校验（未知标红+建议），运行时打错自动纠正（相似度≥0.85）并回写行内。
- 结果框行内展示：有船/模块条件时显示命中原文，无条件时显示在售数量；船厂/改装数据年龄（x小时前/x天前/未知）始终显示。
- 新鲜度集成在船/模块条件行里（卖X且数据N天内新，不再需要独立时间条件）：船看船厂数据时间，模块看改装数据时间，只本地复核；缺时间键或过期都算无法确认而过滤。旧的独立时间条件仍兼容。
- 模块按规格查：主窗口与工程师采购窗口统一使用一栏“规格”（如2C、5A或不限），不再分开选择数字和字母。同一件在售条目必须同时满足名称、等级、级别。服务端条目内多子字段AND，独立条件行分别下推并本地逐件复核；结果及CSV仍将实际名称、等级、级别分列。
- 规格下拉保存真实的“等级＋级别”组合，不做两个列表的笛卡尔积。2026-10-17已核对全部153种内置模组／武器，来源为Spansh实际库存及固定版本的Coriolis规格资料；运行时不下载规格／价格表。Plasma Accelerator仅列2C、3B、4A，Rail Gun列1D、2B。多个精确模块名称取已确认组合的并集，新模块没有可靠组合时只提供“不限”，仍可手填合法格式查询；未收录不等于不存在。主窗口搜索结果会学习并持久化实际组合。
- 旧缓存只有独立等级／级别列表时，保留原信息但不推导组合；新缓存明确保存pairs。旧条件文件及会话中的多等级／多级别、仅限制一个维度的条件不改语义，规格栏以`class=... / rating=...`摘要显示；选择一项新规格才替换旧筛选。未完成的规格草稿可随会话恢复。

## 结果完整性

### 主界面星系详细筛选（v0.1.2）

在 **systems** 模式中，普通条件新增本地数值字段：`station_count`（所有站点，含航母）、`carrier_count`、`minor_faction_count`、`federation_faction_count`、`empire_faction_count`、`alliance_faction_count`、`potential_issuer_count`、`federation_issuer_count`、`empire_issuer_count`。前一组小派系数量包含无政府派系；潜在任务派系估计排除无政府，不保证实时任务。按完整名称忽略大小写去重；必要信息缺失或冲突为未知，不按零处理。缺失站点列表时通过站点接口复核。

点击 **+ 天体／最近有人条件 → 编辑详细条件…**，可添加复用的星球与独立星环条件组。组内条件须由同一颗星球／同一个星环满足，组间可选全部／任一存在；与普通行及其他详细条件行之间均为 AND。原来的 `bodies`／`stations` 字段仍按名称匹配，不等同于新的嵌套编辑器。

同一编辑器还可复核“距离最近人口严格大于指定门槛的星系”，人口门槛可编辑，默认 1。距离上下限都留空则不启用，否则先找最近达标星系，再判断含边界的单边／双边范围；普通参考距离行独立限定搜索区域。原有 `distance_to_nearest_populated_system` 原始字段保持独立，不能视为已按相同人口定义复核。

主界面这些筛选**不附带殖民准入条件**：有居民、有站点或需许可的星系仍可匹配，除非普通行明确排除。派生字段名及条件组不会当作 Spansh 服务端字段发送。先复核普通／距离条件，再计算数量，之后才受控加载完整天体、核实最近邻；缺失证据明确提示，停止时不会接受未验证的候选。诊断也会准备所需的本地证据。

原始编辑草稿、条件文件读取和会话恢复均保留新增行及嵌套组；切换站点模式保留详细草稿，但不能执行仅用于星系的条件。完整详细证据仍在内部结果中保留；CSV 按本次搜索条件展开实际字段、计算数量、匹配星球／星环组及已核实邻近星系名称、人口和距离，不再倾倒整份原始 JSON。普通字段缺失显示未知，不以输入的筛选值冒充实际值。

### PvE 规则（测试中）

- 候选来源与唯一目标配对来自 EDTools PvE。明确 `haz/high/reg/low/res` 作为已确认地点，但若星环数量明确为0，则优先视为无 RES，即使旧地点记录列有 RES 也不命中。按用户约定，有星环视为 **RES（星环推定）**，不推定 Low。没有地点／星环资料的配对显示 **情况未知**，不能把未知当作没有 RES。CNB 不依赖星环，独立判断，仍可用于回退。此修正仅在当前源码，尚未包含在已发布的 v0.1.4-beta.1 EXE 中。
- 距离针对任务来源与参考点。半径 ≤250 ly 使用明确 PHP 网页，接受千分位行数（如 `8,420`），仍核对实际行数并拒绝截断／范围不足。半径 `0` 或 >250 ly 使用公开的 `pve.json` 与 `res.json`，按坐标计算距离，`0` 不做距离过滤；不受网页 250 ly 上限约束。完整数据仅指已返回的 EDTools 记录，不是整个实际银河。
- 来源存在指定派系、来源／目标控制小派系、最少派系／联邦／帝国数量、控制 Power 条件全部 AND。数量输入 `0–8`，联邦和帝国解释为独立的最少数量条件。
- 新增来源停机坪 S/M/L（船型需求，大坪兼容小船）、来源站最大到达 Ls、目标星环最大到达 Ls，全部与原有条件 AND。默认留空不启用，距离 0 为真实上限，包含边界。来源停机坪和距离必须由同一座有 Missions 服务的站点满足；包含地面站，排除航母／Stronghold Carrier／殖民船，并复用殖民船名称／真实名检查，避免被误标 Planetary Outpost 的殖民船入选。记录最近匹配站名、已知最大坪和距离。
- 星环距离由完整 `/bodies/search` 的 `rings` 与 `distance_to_arrival` 计算，不能从星系摘要推断无环；为最近已知有环天体的到达 Ls，不是环半径或具体 RES 距离。其他条件筛完后再批量查询目标，按每组最多 8 个星系、最多 4 个在途请求、完整分页去重／重复页保护、5 分钟缓存处理。未知距离不能算满足显式上限，标记未完成；停止后不返回尚未验证星环条件的结果，也不触发 CNB 回退。
- 当前源码对 EDTools 地点 **情况未知** 的目标，即使星环距离留空也会用 Spansh 天体数据复核。有环升级为推定 RES，不推定 Low；确实返回天体记录、分页取完且未发现星环或异常星环字段时排除。这里仅表示 Spansh 可用数据中无环，不保证游戏内全部天体已探索。无天体覆盖、请求失败或星环数据不确定时保留未知并阻止 CNB 回退；已确认有环但距离未知时，仅在未设距离上限时允许命中。查到星环的证据写入结果／CSV。本功能尚未包含在已发布的 v0.1.4-beta.1 EXE 中。
- **RES 扩展检索（仅当前源码）：**最少任务派系数 **0** 时保留原任务结果并补充 Spansh RES 星系候选，**1–8** 时仅原有任务检索，不另加模式选择。保存的数量（含旧会话中的0）决定行为；0时来源条件停用但保留。新增星系按目标控制小派系／Power、目标半径检索；原任务行保留来源半径／距离含义。Spansh 完整分页（最多100×500），忽略封顶 count，重复页或达到上限报错。天体复用有界批量查询与缓存；无环证据也排除旧任务行，未知覆盖不产生推定命中；不设距离上限时，有环但距离未知仍可命中。Low／普通／High／Haz 或仅明确 RES 必须有明确地点记录。保留原任务配对与数量，复核后更新地点证据，只追加尚无任务结果的目标；沿用“任务来源”列，未收录显示“无数据”，不编造／合并不相关派系数量。有来源优先，再按明确地点、优先 Low、距离排序。EDTools 失败仍保留 Spansh 候选但标记未完成；导入 HTML 只限制原任务部分。尚未包含在 v0.1.4-beta.1 EXE 中。
- 来源站／星环条件以及其结果列已加入中英文界面、CSV 和会话恢复；新增来源星系复制按钮，原双击行为仍复制目标。
- Spansh 控制派系服务器筛选区分大小写：首次空列表时查询正式名称，只接受忽略大小写后的完整名称相等，再以正式大小写重试。不会采用关键词／模糊候选，也不会改写用户输入；名称服务失败会报错，不默认为无控制星系。
- 非零数量条件使用 Spansh 非 Anarchy 小派系数量作为潜在发任务派系估计，并非实时任务数量；重复派系去重。控制 Power 严格使用 `controlling_power`，可指定来源、目标或双方，不使用 `power` 关联名单。
- 先应用全部条件，再选择明确／推定 RES，并单独标注未知地点；Low 只优先排序，不强制，未知排在最后。只有完整检查当前数据集且没有符合条件的明确／推定 RES，也没有地点未知候选，才回退 CNB。缺失关键筛选字段／请求错误／停止时禁止回退。地点未知并不表示检索中断：可以完整检查目录而仍不知道游戏内地点情况。
- 控制小派系条件先分页查询 Spansh 控制星系列表，与 EDTools 配对做精确交集，复用批量响应的派系信息；不依赖可能封顶的 `count` 判断结束。重复分页、字段缺失、上限耗尽会报错，不将不完整列表当作完整覆盖。没有 EDTools 配对的控制星系只计入覆盖诊断，不编造任务目标。
- 控制 Power 同样先查询 `controlling_power` 分页列表并取交集，不使用关联 `power` 名单。分页采用 gzip（服务器不压缩时仍兼容），最多 4 个在途请求、每页 500 条，按页序处理；短页／空页决定覆盖结束，不信任可能封顶的总数，最多可有 3 个已发出的边界外请求，其结果忽略。停止后不再发新请求。只有完整、字段有效的列表才缓存 5 分钟，强制刷新绕过缓存；来源／目标／双方共用同一份列表，并复用其中的派系详情。目标 Power＋来源数量等条件可能仍需查询不在该 Power 列表中的剩余来源，但不再遍历整个任务目录逐一联网。
- EDTools 网页／JSON 缓存 1 小时，Spansh 控制列表／详情缓存 5 分钟，持久化到数据目录的 `pve_cache_*.json`，内存最多 256 个条目。只缓存成功数据；过期或强制刷新失败会报错，不静默回退旧数据。按钮 **刷新数据并查询** 清除导入模式并强制请求本次检索需要的在线数据。
- 星系详情最多 4 个在途请求，按需补充，停止后不再提交；正在执行的 HTTP 请求仍需等待返回／超时。来源／目标配对去重、详情复用，未查询的控制／更新时间字段留空。
- 进度按 150 ms 节流，分解析、下载、控制预筛、详情、复核阶段；记录阶段耗时、缓存获取时间及覆盖／淘汰原因。GUI 每批插入 200 行，批间让出事件循环；不截断实际检索或导出结果。
- EDTools 使用明确的 `/pve.php` 资源，避免无扩展名 `/pve` 在 Apache MultiViews 中与 `pve.json` 冲突产生 HTTP 406。已验证完整在线检索。下载错误保留实际请求地址，支持直接打开网页／保存 HTML 后导入恢复；只有地点／半径的导入检索可离线，额外小派系或 Power 条件仍访问 Spansh。
- 三个小派系字段通过 Spansh `minor_factions?q=` 辅助选完整名称；关键词与相似拼写只用于候选排序，不改变搜索的精确匹配语义，不自动改写输入。联想失败和无候选分别提示，不能解释为不存在；过期输入对应的异步结果不会覆盖当前候选。
- 联想监测实际文本变更（包括粘贴／输入法），保留请求中的真实标点；鼠标按下选择对应候选，取消失效的定时请求，关闭窗口时清理输入追踪及控件引用。

2026-10-14 实测：`Sol / 半径 0 / 最少任务派系 3 / 来源控制 Skyline Monopoly`。在线目录 28,121 个配对；Spansh 507 个控制星系，138 个有目录配对，369 个未收录配对。旧规则下这 138 个目标均无明确 RES/CNB 记录，所以为零结果。新规则复核 138 个来源，1 个数量不足，返回 78 个星环推定 RES＋59 个情况未知，共 137 条；明确 RES 为 0。强制刷新约 13.49 s，紧接着缓存复查约 0.13 s，结果一致，每次仅 6 条进度回调。耗时是本机后端实测，不含 GUI 绘表；第三方数据会变化。

同日 Power 实测：`Sol / 半径 0 / 最少任务派系 3 / Yuri Grom / 来源`，Spansh 返回 1,634 个控制星系，与目录交集 128 个来源；4 个数量不足，最终 124 条（8 个明确 RES、54 个星环推定、62 个未知），无需逐星系详情请求。最初串行、不压缩的批量版本强制刷新约 79.39 s；gzip＋最多 4 页并发后的强制刷新约 15.37 s，紧接着缓存复查约 0.19 s，结果集合一致。双方筛选为 47 条（3 个明确、27 个推定、17 个未知），复用缓存约 0.26 s，两端 Power 已逐行验证。这里是本机实测，不保证其他 Power／网络下的固定耗时。

### 通用检索

- **已达到所需结果数**：返回首批结果，不是全部命中。
- **候选分页已取完**：本次查询的候选已取完；若提示字段缺失，仍存在无法确认的候选。
- **达到翻页上限**：查询尚未完成，0 条命中也不能解释为全库无结果。
- **已手动停止**：返回停止前已确认的结果。正在执行的网络请求会等待返回或超时，然后停止处理。
- **服务器重复返回候选**：停止并提示未完成，避免重复翻页。

Spansh 的候选计数可能封顶在 10000，不能视为全库精确总数。增加翻页上限只能扩大复核量；带本地条件的查询不保证一次请求完成。

## 航母车位查找（v0.1.2）

GUI 的“额外功能 → 航母车位”输入参考星系和半径（默认 30 ly，最大 50 ly），按已收录航母数量筛选范围内的停车候选星系，按距离排序。每页 500 个星系，默认最多 20 页；取完分页与达到页数上限会明确区分。可停止、双击复制星系名、导出 CSV。

- 航母数按站点类型包含 `Carrier` 计数，不区分大小写，包括 Fleet Carrier、Drake-Class Carrier。站点总数仅保留作参考，不再用于推测航母数量或车位。
- 最少／最多航母数为可选非负整数，包含边界；留空不限。最多填 `0` 筛选确认零航母的记录，数量未知不能满足任何数量上下限。
- 缺失或格式错误的站点列表、缺失或空白的站点类型均显示航母数“未知”，不当成 0；明确空站点列表按 0 计。
- 默认数量范围留空，仅显示确认免许可的星系。数量范围及未完成的输入随工具会话保存。
- 这是已收录数量，不是实时航母位置或车位预测。Spansh 数据可能滞后于航母移动；“星系记录年龄”是星系 `updated_at`，不保证每艘航母位置同样新鲜。v0.1.1 EXE 及其截图仍是旧版车位估计工具。

## 稀有商品目标查找器

入口：“额外功能 → 稀有商品目标查找器”。默认参考星系 Ngurii，只能从用户提供的稀有商品来源星系列表中选择（142 个商品条目、138 个不同星系）；可按星系名、商品名或来源站名筛选候选。选择后显示该星系的全部关联商品和来源站，同一星系只列一次，原表 Supply=0 的来源也保留。来源列表内置于 `rare_goods.py`，不使用原表快照的价格、利润、库存和距离。

查询的是距所选商品来源星系 200–220 ly（包含边界，可编辑）的目标空间站，不是查询商品供应站。目标要求大型停机坪，到站距离 ≤100 Ls，排除地面站、航母和殖民船。殖民船同时检查名称、真实名和类型（包括 `$EXT_PANEL_ColonisationShip` 标记），避免 Spansh 将其误标为非地面 Planetary Outpost 时进入结果；在判断距离回退和选前5站之前排除。v0.1.2 更新版 EXE 移除明细表与 CSV 中重复的“范围”列，保留6列：关联势力、星系、空间站、距离 ly、到站距离 Ls、站点记录年龄，查询回退规则不变。

- 下拉选择关联 `Power`，不是 `Controlled`；Arissa Lavigny-Duval 对应 Spansh 名称 `A. Lavigny-Duval`。
- 勾选“全势力扫描”后扫描内置全部 12 个势力，按关联势力分组；同一星系可关联多个势力，组内按星系去重。汇总仅含星系数、到站上限与完成状态，不列命中站点数；点击汇总筛选明细，支持复制星系名、导出全部组 CSV（包括空组）、查看检索说明和停止。
- **每个势力独立回退**：100 Ls 轮分页完整结束且该势力无命中，才查 ≤1000 Ls；标准范围有结果的势力不追加放宽结果。两轮均无命中才显示“无结果”。分页上限、字段缺失、停止或请求失败不解释为无命中。
- 每轮每页 500 条，页数上限分别约束两轮；全势力按势力并集批量查询，再本地分组，避免逐势力重复请求。
- 每个势力先按星系去重，同星系仅保留最近的合格空间站供参考，再按来源到目标的 ly 距离升序、到站 Ls 升序，最多显示 5 个星系；使用未四舍五入的后端 ly 值排序。先完成检索和回退判断，再去重排序截取，不在取得 5 个空间站候选后提前停止。汇总保留全部已确认命中的星系数，明细和 CSV 每星系仅一行，仅包含各组前 5 个目标。
- **状态数据限制**：暂用 Spansh `Unoccupied` 作为 Inara 的 Unoccupied / Expansion / Contested 并集候选；这个合并关系尚未用实际星系样本验证，不保证与 Inara 结果等价。界面保留状态说明，CSV 不附加状态说明列，不能分别筛选 Expansion / Contested。

## 殖民候选星系查找器（v0.1.2）

该工具已包含在 v0.1.2 EXE 中。本版本不包含建设槽位数量筛选；海盗任务查找器仍保持测试中。

v0.1.2 更新版 EXE 移除殖民查找器“最大页数”，忽略旧会话页数限制。候选与最近有人查询自动翻页，直到找到所需结果、读完候选、达到最多结果或手动停止／出错；重复页仍标为不完整，不冒充数据已读完。未限定区域且条件严格时可能查询较久。其他工具的页数设置不变。

v0.1.2 更新版新增：结果及 CSV 展示按 `estimated_scan_value` 降序的前三名已记录星球，包含名称、类型和 Cr，不含恒星，同价按名称排序。缺失／无效／负数估值不当成零，也不以测绘价值替代；缺估值或天体数量不符会标为数据不完整，仅按已知估值排名。复用星系天体摘要或已查询的完整天体，不为价格展示增加额外请求。

最近有人星系仍按人口 >1 判定，人口仅用于内部判断，不再展示为表格／CSV 列；新增复制最近有人星系按钮。最大固定站点停机坪（S／M／L）取自同一最近星系记录，排除航母与殖民船；未知不推测，不改变最近星系选择，也不额外查询。

- 强制三项：`population == 0`、无站点（含航母）、`needs_permit == false`。人口或许可数据未知不入选。星系响应省略 `stations` 时，完整查询站点接口确认无站；不能只凭字段缺失推定为零站点。
- 两套独立的可选 ly 筛选：**区域参考星系＋最大半径**，以及**距最近人口 >1 星系的最小／最大距离**。每套均可留空，同时启用时为 AND。区域半径需要参考星系，最近有人星系距离不需要；距离边界包含，留空不限，0 为真实边界。最近距离支持只填最小值或只填最大值。
- 先找最近有人星系，再判断其距离是否满足上下限，不能改成“距离区间内存在有人星系”。例如要求 5–10 ly，最近有人星系在 2 ly，即使另一个在 8 ly，目标也不合格。查询围绕候选本身的坐标排序，复核人口、坐标距离及返回顺序，不直接采用人口定义未经核实的 `nearest_populated_distance`；不确定记录不能用于确认最近匹配。结果显示最近有人星系名称、距离及最大固定站点停机坪，不显示人口，兼容旧版仅最大距离的保存设置。
- 星系价值门槛独立可选，留空不限；填写后要求严格大于阈值，可选 `estimated_mapping_value`、`estimated_scan_value` 或 `landmark_value`。
- 可添加多个星球条件组，每组任意多条条件，组内所有条件必须由同一颗星球满足。组间 AND 表示每组都存在匹配，OR 表示至少一组存在匹配；同一颗星球可满足多个组。无条件组表示不限。
- 星球组内的星环条件要求该星球自身有符合条件的星环，多条星环条件须由同一个星环满足。独立星环组可由任意天体的星环满足，不要求属于其他组匹配的星球；也支持组间 AND／OR。独立星环区与星球区及其他启用条件之间为 AND。
- 可用属性包括类型、可着陆、地球化状态、重力、到达 Ls、温度、气压、大气、火山活动、大小／质量、自转／轨道属性、储量、地表材料、信号类型／数量及天体扫描／测绘价值。星环字段包括类型、内／外半径及源数据单位的质量。`in` 多选用 `|` 分隔，`between` 范围用 `最小值|最大值`，布尔值用 `true`／`false`。
- 卫星身份按直接行星父级判断；拥有卫星按已记录的直接行星类子天体判断。互绕成员属于**关系推定**：要求同一直接虚拟 `Null` 质心下恰有两颗已记录行星，非零公转周期一致，且没有行星父级信息缺失。仅同绕恒星、潮汐锁定或同一质心不足以判定；复杂／缺失关系为未知。结果展示关联天体名称。不同星球条件组的 AND 不表示各组匹配星球一定彼此互绕。
- 完整天体记录按每批八个星系、最多四个在途天体请求加载。成功的天体／站点复核数据缓存五分钟，刷新绕过缓存。缺失必要属性不能满足正向或否定条件；启用天体／星环条件却无天体记录时，覆盖为未知。
- 结果上限、重复分页和停止均报告不完整；停止时可返回此前确认的部分结果。结果按组展示匹配星球／星环、推定关系，以及启用时的最近有人星系及距离、所选星系价值。支持复制、CSV、中英文和草稿恢复。
- 通用检索和中点结果排除 Spansh 异常 `Test` 星系（ID64 `7780433924818`），通用站点检索也排除其站点。其他名称仅包含 `Test` 的星系不受影响；殖民候选也排除此记录。
